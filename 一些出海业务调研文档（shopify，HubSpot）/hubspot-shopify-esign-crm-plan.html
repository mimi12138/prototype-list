Medora 定制交易 CRM 方案

以 HubSpot 管理客户与交易流程，e签宝管理合同签署，Shopify 管理每次收款与退款；Medora 财务沿用既有受控工具记录预付款账户流水，并将余额汇总回填至 HubSpot。

当前版本：v1.2适用业务：线上问诊 / 来华就医服务数据边界：仅非临床商务信息更新时间：2026-09-02

1. 结论与原则

Medora 的服务流程由 HubSpot、e签宝、Shopify 和既有财务记录协同完成。每位客户可先完成线上问诊，再进入来华就医服务；两项收费分别建立 Deal，来华后的长期服务由 Ticket/Task 跟进。

运作方式：客服在 HubSpot 创建 Contact，并分别建立“线上问诊”和“来华就医服务”Deal；签署、付款和财务核对完成后，将各系统编号及余额汇总回填 Deal，形成完整的客户与交易视图。
客户

Contact

姓名、邮箱、手机号、国家、语言、来源和非临床兴趣。一个客户可以关联多条 Deal。

两类交易

Deal

线上问诊与来华就医服务分别建立 Deal，记录对应报价、签署、付款及关联编号。

服务与资金

Ticket / 财务记录

Ticket/Task 跟进服务执行；既有财务工具记录预付款流水，HubSpot 显示汇总状态。

6. HubSpot 能力、套餐与自动化边界

HubSpot 可以承担 CRM 和流程自动化，但“能管理”不等于“安装后自动流转”。内部提醒和任务可由 HubSpot 配置；表单建 Deal 需要完整工作流；e签宝签署、Shopify 付款与财务余额回写需要以唯一编号为基础的接口集成。

套餐判断：Starter 适合先减少内部提醒和待办的人工操作；要实现“表单提交后自动创建并关联 Deal”等完整业务工作流，需 Professional；Shopify 与 e签宝的跨系统状态联动不由任何 HubSpot 套餐单独提供，仍需 API / Webhook 集成。

7. 客服操作 SOP

7.1 获客与线上问诊

  1. 用邮箱匹配已有 Contact；找不到时创建 Contact，并记录来源、国家、语言和非临床需求。
  2. 创建“线上问诊”Deal，填写报价、币种、A01 签署状态和负责人。
  3. 完成复核后在 e签宝发起 A01；签署完成后在 Shopify 创建问诊费 Draft Order。
  4. Shopify 显示 Paid 后，更新 Deal 并创建资料准备、问诊和方案跟进 Task。

7.2 来华服务签约与预付款

  1. 客户确认医院/医生方案后，在同一 Contact 下创建新的“来华就医服务”Deal。
  2. 完成 B01/B02 签署后，在 Shopify 创建服务费和医疗预付款的 Draft Order；将各订单 ID 回填 Deal。
  3. 财务确认收款后，在既有财务工具建立预付款账户流水；将账户编号、累计预付款、上次对账余额和最近对账时间回填 Deal。
  4. 创建关联 Ticket/Task，交接行前安排、落地复签、到院服务和后续结算。

7.3 服务执行、结算和退款

  1. Ticket/Task 跟进行前安排、落地复签、到院就诊、余额预警、补款、治疗结束和深度回访。
  2. 财务在既有受控工具中记录医院、第三方和现场服务的逐笔费用；HubSpot Deal 仅更新累计支出、累计退款、上次对账余额、余额状态和最近对账时间。
  3. 费用核对完成后记录 D03 编号；需要退还结余时在 Shopify 执行 Refund，并将退款金额、Refund ID 和状态回填 Deal。
邮箱是关键匹配键：Shopify Checkout 已设置邮箱必填。客服在创建 Contact、Deal、e签宝和 Draft Order 时必须使用同一个经确认的邮箱，避免 Order 同步后出现无关联 Contact。

8. 控制点与数据边界

  • 线上问诊费与来华服务费/医疗预付款分别建立 Deal 和 Shopify 订单。
  • 未签署完成不得发送对应 Shopify 付款链接；线上问诊使用 A01，来华服务使用 B01/B02。
  • 报价金额变化必须新建版本，并重新复核。
  • 同一 transaction_id 不得存在多个有效未支付 Draft Order。
  • Shopify 记录实际支付和退款；e签宝保存合同原件与签署证据；HubSpot 保存关联 ID 和业务汇总。
  • 预付款账户逐笔流水由财务在既有受控工具中管理；HubSpot Deal 只回填累计金额、上次对账余额、状态和最近对账时间，不作为实时资金账本。
  • HubSpot、Shopify、e签宝、WhatsApp、邮件、日志和普通表单均不得存放诊断、病历、影像、报告或治疗方案。
  • 付款链接只发给已核对的收件人，不粘贴到公开文档或群聊。
系统状态管理规则：发生金额争议时，以财务记录、Shopify Order/Refund 和原始凭证为准；发生签署争议时，以 e签宝签署证据为准。HubSpot 用于汇总状态、分配任务和客户沟通。

9. HubSpot 准备与测试清单

Shopify Order 已完成同步后，按以下顺序在 HubSpot 中做准备和验证。所有测试优先使用测试联系人、测试 Deal 和测试订单，避免修改真实业务记录。

1

配置默认销售管道

当前免费版使用已有“销售管道”，用于两类 Deal 的签约与付款进度。

  • 需求确认 → 待复核 → 待签署
  • 签署完成 → Draft Order 已创建 → 付款链接已发送
  • 已完成 / 已付款（Won）
  • 已取消（Lost）；异常使用字段和 Task 处理
2

创建 Deal 自定义字段

为“线上问诊”和“来华就医服务”两类 Deal 配置共同字段和专属字段。

  • 交易类型、交易编号、报价编号、报价版本
  • A01 或 B01/B02 文档 ID、签署状态
  • Draft Order / Order ID、付款状态
  • 预付款账户编号、余额汇总、D03 编号
3

创建两类测试 Deal

在同一测试 Contact 下分别创建线上问诊 Deal 和来华服务 Deal。

  • 线上问诊 Deal 关联问诊费订单
  • 来华服务 Deal 关联服务费/预付款订单
  • 为来华服务创建关联 Ticket/Task
  • 确认 Contact、Deal、Order 可以互相跳转
4

建立保存视图

将销售交易和服务执行分别形成常用工作列表。

  • 待复核、待签署、付款链接已发送
  • 线上问诊已付款
  • 来华服务已付款待交接
  • 余额预警、待补款、异常状态为待处理
5

测试 Task 和负责人

验证问诊、签署、付款核对、行前、结算和退款任务的分配。

  • 指定负责人和截止时间
  • 确认负责人能看到任务和提醒
  • 确认任务出现在 Deal/Contact 时间线上
6

验证订单同步

用 Shopify 中的状态变化检查 HubSpot Order 是否更新。

  • 核对订单金额、币种、状态
  • 确认订单关联到正确 Contact
  • 确认 Order 状态在 Shopify 维护
  • 记录同步延迟和异常情况
完成标准：客服可以从一个 Contact 查看两类 Deal、关联 Shopify Order 和服务 Task；财务人员可将预付款账户编号、余额汇总和 D03 编号回填来华服务 Deal；逐笔资金流水继续保留在既有财务记录中。

10. 落地顺序

第 1 步 · 前置确认

确认订阅和权限

确认当前 HubSpot 是否支持 Deal 字段、Pipeline、Task，以及后续需要的自动化和阶段权限。功能可用范围取决于实际套餐。

第 2 步

配置 Deal 模型

建立字段、阶段、负责人和保存视图；把关键字段放到 Deal 记录页。

第 3 步

跑通人工闭环

用测试邮箱完成 Contact → Deal → e签宝 → Draft Order → 支付 → Order 同步 → 退款演练。

上线前必须确认：客户当前 HubSpot 套餐和用户权限是否支持 Deal 自定义字段、Pipeline、Task，以及计划启用的工作流和阶段权限。确认后再进行正式配置。
MVP 推荐配置：Deal 自定义字段 + Deal Pipeline + Task + Shopify Order 同步 + e签宝文档 ID 手动关联。先验证 3–5 笔真实定制交易，再启用自动化。
