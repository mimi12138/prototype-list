子公司 B 如何加入主公司、接收广告客户并在 HubSpot 中隔离

这张图只讲一条完整链路：主公司账号 A 配置用户和权限 → B 投放广告 → 客户提交回电表单 → HubSpot 自动判断归属 → B 在 CRM 里看到自己的客户。

讨论版 · 当前假设：一个主公司 HubSpot 门户，多家子公司作为用户和 Team 加入

唯一主链路：从 B 加入到 B 看到客户

每一步都标注“谁做”和“在哪里做”

01 · 主公司

邀请 B 的员工

不新建 HubSpot 门户。A 账号把 B 的员工邮箱邀请成用户。

Settings → Users & Teams → Add users›
02 · 主公司

建立 B Team

把 B 用户放进“B 子公司 Team”，并设为 Main Team。

Settings → Users & Teams → Teams → Create team›
03 · 主公司

限制 B 的联系人

B 用户只看自己 Team 的联系人；不要给 B 全量表单提交权限。

Users → B 用户 → Access → Edit permissions → CRM → Contacts›
04 · B 子公司

投放广告并带标识

广告链接携带你们定义的 B001 和广告平台的 campaign_id。

广告平台 Final URL / URL 参数›
05 · 官网

保存并提交标识

Hydrogen 读取 URL 参数，保存到 Cookie/localStorage，提交表单时写入 HubSpot。

cmedtrip.com → HubSpot Forms API›
06 · HubSpot

Workflow 自动分配

客户提交后，HubSpot 创建或更新联系人；满足条件后设置 Owner 和状态。

Automation → Workflows → Create workflow›
07 · B 子公司

在 CRM 查看客户

B 用自己的邮箱登录主公司门户 A，在 CRM Contacts 里看到分给 B Team 的客户。

CRM → Contacts → B 待跟进视图
最容易混淆的点：“表单提交记录”和“CRM 联系人”是两个入口。B 用户建议不开放 Marketing → Forms → View submissions，而是通过 CRM → Contacts 查看已经分配给 B 的联系人。

三种结果

Workflow 的默认分支必须兜底

B001 匹配成功

Contact owner = B 负责人；Owner team = B Team；B 用户可以看到。

没有标识 / 找不到计划

attribution_status = manual_review；进入主公司分诊队列，不误分配。

第二次换成 C

保留首次 B 归属，记录 latest_touch=C；标记 conflict，主公司决定是否改派。

HubSpot 页面怎么配置

以下操作都在主公司账号 A 中完成

① 邀请 B 用户并设置席位

B 不需要单独注册一个 HubSpot 门户。

路径：Settings → Users & Teams → Add users → 输入 B 的员工邮箱 → 选择 seat / 权限 → Send invite。

收到邀请后，B 点击邮件链接接受邀请，并自行设置密码。以后用自己的邮箱登录主公司账号 A。

席位建议：只做 CRM 跟进，先让 HubSpot 报价确认 Core/CRM access；需要 Sales 功能或轮询分配，再确认 Sales seat；需要客服工单，再确认 Service seat。

② 创建 B Team

Team 是用户分组，不是另一个 HubSpot 账号。

路径：Settings → Users & Teams → Teams → Create team → 输入“B 子公司 Team” → Team Members 选择 B 用户 → Save。
设置主 Team：Settings → Users & Teams → B 用户 → Setup → Teams → Main Team = B 子公司 Team。

建议 B 用户不要同时加入 A、C 等其他子公司 Team。

③ 设置 B 的联系人访问权限

这一步决定 B 能不能看到别人的联系人。

路径：Settings → Users & Teams → Users → 点击 B 用户 → Access → Edit permissions → CRM → CRM Objects → Contacts。
权限建议设置
View contactsTheir team's contacts
Edit contactsTheir team's contacts
Delete contactsNone
Forms → View建议关闭，避免看到全量提交列表

④ Contact owner 是什么

它就是“这个联系人由哪个 HubSpot 用户负责”。

查看路径：CRM → Contacts → 打开联系人 → Actions → View all properties → 搜索 Contact owner。

例如：

Contact owner = B负责人
Owner team = B 子公司 Team

只有当联系人 Owner 被设置为 B Team 的用户，B 的“仅查看自己 Team”权限才会生效。

⑤ Workflow 创建入口（你之前没找到的地方）

不是在联系人详情页创建，而是在 Automation 菜单创建

进入路径：登录主公司账号 A → 顶部导航 Automation → Workflows → 右上角 Create workflow → From scratch → 选择 Contact-based。
步骤页面操作示例
1Enrollment triggersfranchise_id is known 且 attribution_status is not matched
2添加 If/then branchfranchise_id = B001
3Action → Edit recordContact owner = B负责人；assigned_franchise_id = B001；status = matched
4Action → Create task给 B负责人创建“联系新预约客户”任务
5默认分支missing / invalid / conflict → 主公司分诊负责人
6Review and turn on先用测试邮箱提交一条 B001 表单，再开启
触发时间：表单提交后，HubSpot 创建或更新联系人；满足 Enrollment triggers 后进入 Workflow。通常接近实时，但可能有 API 或队列延迟。老联系人是否再次触发，要看 Re-enrollment 设置。

字段和归属规则：各放在哪里

只出现一次，避免把“规则表”和“客户记录”混为一谈

广告映射表（前期 Excel）

保存“广告计划属于哪个子公司”的规则。前期不用开发 B 端系统。

字段示例
franchise_idB001
franchise_nameB 子公司
hubspot_team_nameB 子公司 Team
default_owner_emailb-owner@example.com
platform / ad_account_idGoogle Ads / 123-456
campaign_id987654321
ad_group_id / ad_id可选
status / effective datesactive / 生效停用日期

HubSpot 联系人属性

保存“某个客户实际从哪个广告进来”的结果。

字段用途
franchise_id本次表单携带的子公司 ID
campaign_id本次表单携带的广告计划 ID
ad_account_id / ad_group_id / ad_id可选的广告层级字段
utm_source / medium / campaign渠道分析
first_touch_franchise_id首次归属，默认锁定
latest_touch_franchise_id最近一次触达
attribution_statusmatched / missing / invalid / conflict
routing_error人工复核原因
一句话：Excel 保存映射规则，联系人属性保存实际点击结果。Workflow 可以先按 franchise_id 分配；正式上线建议用 campaign_id → franchise_id 映射先校验，再执行分配。

重复提交的默认处理

推荐“首次归属锁定，后续触达记录下来”

首次 B001

first_touch=B001；Contact owner=B负责人；status=matched。

后来 C001

first_touch 保持 B001；latest_touch=C001；status=conflict；不自动改 Owner。

后来无参数

保持原 Owner；status=missing；不把客户清空或错误分给主公司。

套餐门槛与报价确认

Team 和 Workflow 是两个需要分别核对的能力

测试账号实测：Breeze 助手提示当前账号无法创建 Workflow，需要升级；页面显示该自动化能力“在 Sales Hub Professional 上可用”，并提供 14 天试用。因此，Workflow 不能再按“可能需要 Professional”描述，而应按 Sales Hub Professional 作为本账号的直接升级候选。
项目目前已知信息报价时必须确认
Workflow 自动化测试账号当前不可用；Breeze 页面显示 Sales Hub Professional 可用，并有“开始 14 天试用”。Sales Hub Professional 的月费/年费、试用结束后的价格、是否包含 Contact-based Workflow、分支、Edit record、Contact owner、任务和内部通知。
Teams此前 HubSpot 页面提示通过 Marketing Hub Professional 访问团队。Marketing Hub Professional 是否可以创建多个 Team、加入用户、设置 Main Team，并按 Team 限制 Contacts 的 View/Edit。
联系人隔离需要 B 用户使用 Their team's contacts。确认该权限在购买的具体 Hub/版本中是否可用，以及是否还需要额外付费席位。
轮询分配如果 B Team 有多人，可在 Workflow 中轮询。确认是否必须购买 Sales/Service Professional seat，以及每个用户的席位类型。
自定义对象用于未来在 HubSpot 里直接管理 Franchise / Ad Campaign。确认是否需要 Enterprise；MVP 先用 Excel，不把它作为首期购买条件。
Marketing Contacts表单会创建或更新联系人。确认是否自动计入 Marketing Contacts 额度、额度大小和超额价格。
用户席位B 用户需要登录主公司门户。分别报价 Core/CRM access、Sales seat、Service seat，不要只问“增加用户”的价格。
实施费用官网参数、联系人字段和 Workflow 仍需配置。确认权限配置、Workflow 搭建、数据迁移、培训和支持是否另收费。
购买判断：如果目标只是创建 Team，重点确认 Marketing Hub Professional；如果目标是让表单提交后自动分配 Owner，当前测试账号已经明确指向 Sales Hub Professional。两者要让销售分别写入报价包，不能用一个模糊的“Professional”代替。
